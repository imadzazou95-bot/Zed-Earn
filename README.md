# Zed Earn 🇩🇿 — PWA affiliate-marketing platform

**Zed Earn** is an Algerian affiliate-marketing app: users complete marketing micro-tasks and earn
commissions in **Algerian Dinar (DZD)**. Built with Expo + React Native + TypeScript, it ships as a
**installable PWA** (service worker, manifest, offline shell) and runs natively on iOS/Android.

Mobile-first layout capped at 480 px · dark/light theme · AR (RTL) / FR / EN i18n · local-first storage.

## 2. PWA

```
public/
├── manifest.json     name, icons (192/512/maskable), shortcuts, standalone, theme colors
├── sw.js             network-first navigation + stale-while-revalidate assets + offline fallback
├── offline.html      branded offline shell
├── robots.txt
└── icons/            generated by scripts/gen-icons.js (pure-JS PNG encoder, no native deps)
```

* `scripts/pwa-postbuild.js` copies `public/ → dist/` and injects manifest link, theme-color,
  apple-touch metas, Open Graph tags and the service-worker registration into `dist/index.html`.
* `lib/pwa.ts` handles runtime registration, `beforeinstallprompt` capture (**Install app** button),
  online/offline detection and an **update available → reload** banner when a new SW is waiting.

```bash
npm run build:pwa     # icons + expo export --platform all + PWA post-build
```

## 3. Roles & permissions

| Role | Capabilities |
| --- | --- |
| `user` (affiliate) | accept tasks, submit proofs, withdraw (after KYC), referrals |
| `merchant` | everything above + create campaigns (requires **approved KYC**) |
| `admin` | review proofs / KYC / withdrawals / campaigns, enable-disable tasks, read audit log |

Admin mode is unlocked with an access code (demo PIN `2468`, hashed comparison, rate limited to
5 attempts / 15 min) from **Profile → Administrator access**, and can be revoked at any time.

## 4. Compliance state machines

```
KYC:         none ──submit──▶ pending ──▶ approved
                                   └────▶ rejected (reason) ──resubmit──▶ pending
Proof:  available ─accept─▶ accepted ─submit─▶ review ──▶ completed (commission credited)
                                                   └────▶ rejected (reason, max 3 resubmits)
Withdraw:            pending (funds locked) ──▶ approved (ledger debit)
                                            └─▶ rejected (reason, funds released)
Campaign:            pending ──▶ approved (task goes live) / rejected (reason)
```

A demo auto-reviewer settles anything an admin has not handled (proofs 20 s, KYC 18 s, payouts 25 s)
so the flows always complete; in production these are human/back-office decisions.

## 5. Money rules (`lib/policy.ts`)

* Task commission credited in full **+ level bonus**: Beginner 0% · Active 3% · Pro 7% · VIP 12%.
* Referral: 500 DZD on a friend's first completed task + 5% lifetime share.
* Withdrawal fees: CCP 1% (30–300) · e-wallets 1.5% (20–250) · card 2% (50–400).
* Limits: min 1,000 DZD, max 100,000 DZD per request and per day; KYC required.
* Merchant campaign cost: reward + 10% platform fee, reward between 100 and 20,000 DZD.

## 6. Tamper-evident ledger

Every settled movement is an append-only entry carrying `seq`, `prevHash` and
`hash = SHA-256(seq|kind|type|amount|ref|date|prevHash)` — a hash chain seeded with a genesis hash.
`verifyChain()` walks the chain chronologically and reports the first broken entry; users can run it
from **Wallet → Verify ledger** and admins see the chain HEAD in the console.
The SHA-256 implementation is dependency-free and was verified against Node's `crypto`.

## 7. Security layer (`lib/security.ts`)

* **Rate limiting** — sliding-window buckets with lockout, persisted: OTP send/verify, auth submit,
  withdrawals, KYC submissions, campaign creation, chat, admin PIN, demo deposits.
* **Session guard** — signed-ish token + sliding 24 h expiry, revalidated on boot, refreshed on
  navigation, watchdog every 30 s, automatic logout with an explanatory toast.
* **Validation** — phone, email, name, birthdate (18+ check), CCP (10–12 digits), amounts, text
  lengths; inline red field errors + `sanitize()` stripping control characters before storage.
* **Audit log** — every user/admin/auto/system action recorded (max 200 entries) for traceability.
